# is-module-reset

[![GitHub License](https://img.shields.io/github/license/jekyll-is/is-module-reset)](LICENSE)
[![Gem Version](https://badge.fury.io/rb/is-module-reset.svg)](https://badge.fury.io/rb/is-module-reset)
![Coverage](coverage-badge.svg)

Сохранение и восстановление состояния модулей и классов Ruby **при тестировании**:
переменных классов (`@@var`) и переменных экземпляра самих модулей и классов
(`@var`). Гем нужен, чтобы тесты, которые меняют глобальное состояние
(синглтоны, реестры, кэши, настройки, хранимые в модулях), не влияли друг на
друга.

> **Не предназначен для использования в продакшене.** Гем не создаёт
> по-настоящему изолированного окружения: он лишь возвращает значения в те же
> самые объекты.

English version: [README.md](README.md)

## Установка

Добавьте в Gemfile:

```ruby
gem 'is-module-reset', group: :test
```

Или установите напрямую:

```bash
gem install is-module-reset
```

## Быстрый старт

```ruby
require 'is-module-reset'

module App
  @@requests = 0
  @settings = { debug: false }

  def self.requests
    @@requests
  end

  def self.hit!
    @@requests += 1
  end

  def self.settings
    @settings
  end
end
```

Выполнить блок и откатить все изменения после него:

```ruby
IS::ModuleReset.isolate(App) do
  App.hit!
  App.settings[:debug] = true
  App.requests   # => 1
end

App.requests     # => 0
App.settings     # => { debug: false }
```

Или сделать снимок и восстановить его вручную:

```ruby
state = IS::ModuleReset.dump(App)

App.hit!
App.settings[:debug] = true

IS::ModuleReset.undump(state)

App.requests     # => 0
App.settings     # => { debug: false }
```

## Что сохраняется

Для каждого переданного модуля или класса и для каждого модуля или класса,
достижимого из него через константы (рекурсивно, учитываются только собственные
константы модуля, то есть `Module#constants(false)`), гем сохраняет:

- переменные классов, определённые в самом этом модуле (унаследованные не
  включаются);
- переменные экземпляра самого объекта-модуля (`@var`, заданные на уровне модуля
  или класса, в том числе созданные через `attr_accessor` в `class << self`).

При восстановлении все такие переменные удаляются, а сохранённые задаются
заново. Поэтому переменные, созданные после снимка, исчезают, изменённые
возвращают прежние значения, а удалённые появляются снова.

Значения копируются через `deep_dup` из [is-deep](https://github.com/inat-get/is-deep):
`Hash` и `Array` копируются рекурсивно (общие и циклические ссылки сохраняются),
модули и классы остаются как есть, остальные объекты копируются через `dup`
(если объект не копируется, остаётся тот же самый объект). Восстановление тоже
работает с копией, поэтому один и тот же снимок можно восстанавливать сколько
угодно раз.

## API

### `IS::ModuleReset.dump(*mods) → Hash`

Делает снимок переданных модулей и всего, что достижимо из них через константы.
Возвращаемый хэш является внутренним представлением: рассматривайте его как
непрозрачное значение и передавайте в `undump`.

### `IS::ModuleReset.undump(state)`

Восстанавливает состояние из снимка, который вернул `dump`. Можно вызывать
несколько раз с одним и тем же снимком.

### `IS::ModuleReset.isolate(*mods) { ... }`

Делает снимок, выполняет блок и восстанавливает снимок после него, даже если
блок выбросил исключение. Возвращает значение блока. Если блок не передан,
бросает `ArgumentError`.

## Интеграция с тестовыми фреймворками

### RSpec

Изолировать каждый пример:

```ruby
RSpec.configure do |config|
  config.around do |example|
    IS::ModuleReset.isolate(MyApp) { example.run }
  end
end
```

Хуки `around` оборачивают хуки `before` и `after`, поэтому изменения, сделанные
в них, тоже откатываются.

Или восстанавливать состояние, зафиксированное в начале прогона:

```ruby
RSpec.configure do |config|
  baseline = nil
  config.before(:suite) { baseline = IS::ModuleReset.dump(MyApp) }
  config.after(:each)   { IS::ModuleReset.undump(baseline) }
end
```

### Minitest

```ruby
class Minitest::Test
  def setup
    super
    @module_reset_state = IS::ModuleReset.dump(MyApp)
  end

  def teardown
    IS::ModuleReset.undump(@module_reset_state)
    super
  end
end
```

Если ваши тестовые классы определяют собственные `setup` и `teardown`, вызывайте
в них `super`.

## Ограничения

- **Константы не восстанавливаются.** Ни переопределённые, добавленные или
  удалённые константы, ни содержимое изменяемых констант (`CONFIG = {}`).
- **Сохраняется только состояние на уровне модулей.** Глобальные переменные
  (`$var`), `ENV`, thread-local переменные, переменные экземпляра обычных
  объектов и всё за пределами переданных пространств имён не затрагиваются.
- **Значения являются копиями.** Объекты, кроме `Hash` и `Array`, копируются
  поверхностным `dup`: их внутреннее изменяемое состояние общее с оригиналом, а
  после восстановления в модуле лежит копия, а не исходный экземпляр. Если вы
  храните, например, объект-синглтон в `@instance`, то после восстановления это
  может быть уже другой объект.
- **Копии не заморожены.** Замороженное значение после восстановления становится
  изменяемым.
- **Константы обходятся без разбора.** Алиас на модуль из другого пространства
  имён (`Log = ::Logger`) попадёт в снимок и тоже будет откатываться. Кроме
  того, при обходе могут загружаться константы с `autoload`.
- **Не потокобезопасен.** Гем меняет глобальное состояние, поэтому не используйте
  его при параллельном запуске тестов в потоках одного процесса. Параллелизм на
  процессах не мешает.
